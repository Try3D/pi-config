Postgres vs ClickHouse

Picking a store for analytics workloads

Frame this as a workload question, not a winner question. Nobody is replacing Postgres wholesale.

Storage

Storage model

Row store

Whole rows together. Fast single-record reads and writes.

Column store

One column together. Fast scans over a few fields.

Consequence

The storage choice picks the workload for you.

This single decision explains almost everything that follows. Don't rush it.

40x fewer bytes

Same query, same data, columnar layout.

Numbers vary by schema. The order of magnitude is the point.

The query that decides it


            SELECT toStartOfHour(ts) AS h, count()
            FROM events
            WHERE ts > now() - INTERVAL 7 DAY
            GROUP BY h
Touches two columns across a week. Row storage reads every column to answer it.

Write path

  • Row inserts, one at a time — Postgres
  • Batched inserts, thousands at a time — ClickHouse
  • Small frequent writes are the failure mode
Hold the third line back — it's the thing teams get wrong first.

Transactions

Where the two genuinely diverge.

Press down if anyone asks for specifics.

Postgres

Full ACID, per statement, across tables.

ClickHouse

Atomic per insert. No cross-table transactions.

How to choose

  • Serving individual records — Postgres
  • Aggregating over billions of rows — ClickHouse
  • Both, usually — Postgres for state, ClickHouse for analytics
Land on "both". Most teams here already run Postgres and are adding, not migrating.
